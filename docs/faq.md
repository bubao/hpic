# 常见问题排查 (FAQ)

本文档整理了使用 hpic 过程中的常见问题与排错方法。

---

### 1. 为什么部分图片在浏览器中能看，但在客户端内显示 404？
- **原因**：部分图床服务配置了防盗链机制，会严格校验 HTTP `Referer`。在应用中直接加载时会被图床判定为非法盗链而返回 403 或 404。
- **排查**：hpic 内置了防盗链安全代理。当图片直接加载失败时，会自动回退通过后端的 `/api/image/proxy` 加载（自动剥除 Referer 并走配置中的代理），通常无需手动干预。

---

### 2. 为什么不再提供 Unsplash AccessKey 输入，网络搜图受阻怎么办？
- **原因**：Unsplash 官方 API 获取的图片地址属于海外 CDN，即使配置了官方 AccessKey，读者在国内打开博客时仍可能因网络受阻而导致图片加载缓慢或裂开。
- **解决方法**：
  1. hpic 已全面切换为开箱即用的免 Key 检索引擎，自动抓取高清横屏图源，并支持平滑降级至超高清 Wallhaven 壁纸；
  2. 若处于国内受限网络环境，可在【设置】中的【代理地址】填入本地代理端口（如 `http://127.0.0.1:7890`），搜图与图片加载将直接提速；
  3. 切换至顶部【Wallhaven 壁纸】源进行搜图，其国内直连连通率明显更优。

---

### 3. 如何一次性打包生成 Windows、Linux 与 macOS 的全部安装包？
无需配置繁重的 Docker 或分别在三台电脑上编译，在项目根目录下直接运行：
```bash
make dist
# 或运行：
./scripts/build-all.sh
```
Go 语言原生交叉编译引擎会在十余秒内自动生成：
- Windows 64位压缩包 `hpic-windows-amd64.zip`（内含安装器 `install.ps1` 与卸载程序 `uninstall.cmd`）
- Linux 双架构包 `hpic-linux-amd64.tar.gz` 与 `hpic-linux-arm64.tar.gz`
- macOS 双架构包及原生 DMG 磁盘映像安装包 `hpic-macOS.dmg`
- 存放于 `dist/` 目录中，并带有 `checksums.txt` 校验和。

---

### 4. Windows 下如何彻底干净卸载 hpic？
hpic 遵循 Windows 现代化软件安全卸载规范，绝无后台垃圾残留：
- **方式一（系统设置卸载）**：直接打开 Windows 10/11 的【设置 ➔ 应用 ➔ 已安装的应用】，找到 **hpic** 点击【卸载】；
- **方式二（双击脚本卸载）**：进入安装目录 `%LOCALAPPDATA%\Programs\hpic`，双击运行 `uninstall.cmd`（或右键运行 `uninstall.ps1`）；
- 卸载程序将全自动终止正在运行的进程、移除桌面与开始菜单快捷方式、从用户 PATH 环境变量中剔除安装路径、清除注册表记录并销毁程序目录。

---

### 5. 为什么切换图片时会先清空旧图？
为了杜绝浏览器在请求新图网络延时期间一直显示“上一张旧图残影”的割裂感，hpic 采用了“变更即清空 $\rightarrow$ 骨架微光流光 $\rightarrow$ 新图就绪淡入”的严密生命周期，确保每次图片更换都能呈现平滑的微缩放与模糊展开动画。

---

### 6. 为什么所有图片（Unsplash、Wallhaven、收藏夹、SVG 等）都能看到具体尺寸和文件名了？
- **机制升级**：过去由于外部平台数据结构差异，部分源（如 Wallhaven）有尺寸元数据，而 Unsplash 或本地动态生成的 SVG 没有。
- **现行方案**：系统在服务端爬虫层进行了精确整型提取，并在前端渲染层通过浏览器的 `HTMLImageElement.naturalWidth` 与 `naturalHeight` 进行双重测量。无论图片来源何处，只要渲染就绪，右下角与灯箱顶部均会展示其实际物理分辨率（如 `3840×2160`）、标准宽高比（如 `16:9`、`21:9`）以及推导出的直观文件名。

---

### 7. 如何增加 Hexo 主题所需的自定义封面字段？
不同主题对封面字段的命名不同（如 `cover`、`banner_img`、`index_img`、`thumbnail` 等）。
- **操作**：点击右上角【设置】➔【博文封面 Frontmatter 字段】，直接输入新增的字段名称（如 `cover`）并回车添加。主界面封面区与配图面板将自动为其生成对应的操作按钮与写入卡片。

---

### 8. Git 部署提示输入密码或超时挂起？
- **原因**：通过 HTTPS 地址操作且未开启系统凭据记住时，后台 Git 进程等待输入用户名/密码会导致挂起超时。
- **解决方法**：
  - 推荐为 Hexo 仓库配置 SSH 地址（`git@github.com:...`）；
  - 或配置系统的 Git 凭证助手：
    ```bash
    git config --global credential.helper osxkeychain   # macOS
    git config --global credential.helper wincred       # Windows
    git config --global credential.helper store         # Linux
    ```

---

### 9. 图床健康体检会消耗很多网络流量吗？
- **完全不会，几乎零流量消耗！**
- **检测机制**：体检引擎默认使用 **HTTP HEAD 协议**，仅仅请求图床服务器返回几百字节的 HTTP Header 状态码（200/404 等），**图片本身的 Body 内容下载量严格为 0 字节**；
- **防盗链降级**：即便遇到少数禁用 HEAD 方法的严格防盗链 CDN，系统也会通过 `Range: bytes=0-1024` 头仅请求前 1KB 数据切片验证连通性，并在获取状态后立即关闭连接，绝不会下载几 MB 的整张大图，扫描成百上千篇博文流量消耗通常不足几百 KB。

---

### 10. 如何检查更新并升级到最新版本？
hpic 支持多种现代化更新途径：
1. **客户端顶栏按钮**：界面顶部常驻【更新】按钮。当有新版本时会自动高亮提示，点击即可查看 Release Notes，并支持**“一键自动下载安装”**进行热替换升级；
2. **静默自动感知**：客户端在后台每 10 分钟自动对 GitHub Releases API 进行一次轻量静默轮询，无需手动刷新；
3. **命令行终端更新**：在任意终端执行 `hpic update`，自动检测、列印日志并就地替换为最新二进制。

---

### 11. 终端支持哪些常用 CLI 子命令？
无需启动图形界面，直接在终端中运行即可执行快速维护：
```bash
# 查看当前版本、Git 提交哈希与构建时间
hpic version

# 查看全量版本更新历史 (CHANGELOG)
hpic changelog

# 检查 GitHub Releases 并自动下载就地升级
hpic update

# 交互式完全卸载当前系统中的 hpic 及其桌面集成
hpic uninstall

# 查看命令行参数帮助
hpic help
```

---

### 12. Linux (Ubuntu / Debian) 如何使用原生 `.deb` 安装包？
从 GitHub Releases 下载对应的 `hpic_*_amd64.deb` 或 `hpic_*_arm64.deb` 包后：
- **安装**：
  ```bash
  sudo dpkg -i hpic_*_amd64.deb
  # 或使用 apt 自动补齐依赖
  sudo apt install ./hpic_*_amd64.deb
  ```
- **卸载**：
  ```bash
  sudo apt remove hpic
  ```
- 安装完成后，系统应用程序菜单会自动出现 **hpic** 快门图标，终端也可直接执行 `hpic`。

### 13. macOS 打开应用提示“无法打开，因为 Apple 无法检查其是否包含恶意软件”？
- **原因**：本地编译的二进制未经 Apple 商业付费公证证书签名。
- **解决方法**：
  - 在 `~/Applications` 中找到 `hpic.app`，**按住 Control 键并点击鼠标**，在弹出菜单中点击【打开】，并确认运行；
  - 或在终端中执行：
    ```bash
    xattr -cr ~/Applications/hpic.app
    ```

### 14. 代理地址需要账号密码认证（或密码含特殊字符）如何配置？
- **支持格式**：hpic 内置专用的代理解析器，原生支持标准 HTTP 及 SOCKS5 代理认证格式：
  ```
  http://username:password@127.0.0.1:7890
  socks5://username:password@127.0.0.1:1080
  ```
- **特殊字符容错**：即使密码中包含 `@`、`:`、`#` 等特殊符号，系统也会通过专用的 URL 凭据构造器正确解析，不会引起 URL 截断或 407 Proxy Authentication Required 报错；
- **连通性校验**：在【设置】面板的代理输入框旁，点击【测试代理】按钮即可即时验证代理是否通畅。

---

### 15. 文章保存在分类或年份等多级子目录下（如 source/_posts/tech/2026/），能被正常识别吗？
- **完全支持**：hpic 会深度递归遍历 `source/_posts` 与 `source/_drafts` 目录下的所有嵌套子文件夹，无需将所有 `.md` 文件平铺在根目录下；
- **隐藏文件夹自动跳过**：扫描时会自动忽略以点开头的隐藏目录（如 `.git`、`.obsidian`、`.trash` 等），避免误加载非博文文件；
- **跨目录重名防护**：即使不同分类子目录下存在同名文章，系统内部也会以绝对文件路径作为唯一标识进行精确隔离。

---

### 16. 在灯箱大图预览中发现图片 404 失效，退出预览后会怎样？
- **全局闭环状态同步**：系统实现了失效配图闭环追踪。当你在灯箱预览或卡片加载中触发 404 错误时，该 URL 会立即被捕获并登记到全局失效清单中；
- **退出灯箱后的界面联动**：
  1. **封面编辑区**：失效字段自动标红高亮，右上角标注醒目的 `404 失效` 红色徽章，顶部常驻展示黄色警告横幅并提示一键更换；
  2. **侧边栏文章项**：对应文章右侧的状态徽章会即时由绿色/蓝色切换为红色的 `配图失效` 徽章；
  3. **图库与收藏夹**：该失效图片卡片自动降低饱和度并添加 `404 失效` 标记，防止博主误选或重复使用。

---

### 17. 为什么运行 make release 发版会中止，提示 CHANGELOG.md 中未找到版本章节？
- **设计原因**：hpic 严格遵循高质量开源软件的文档驱动发布规范。为了避免把零散、碎片化的 Git Commit 直接推送给用户，发布向导**严格以 `CHANGELOG.md` 为唯一事实依据**；
- **解决方法**：
  1. 打开根目录下的 [CHANGELOG.md](../CHANGELOG.md)；
  2. 在第一条分割线 `---` 下方，新增拟发布版本的章节（例如拟发布 `v0.0.1`）：
     ```markdown
     ## [v0.0.1] - 2026-11-04

     ### 新增特性 / 修复优化
     - 详细变更说明 1
     - 详细变更说明 2
     ```
  3. 保存后重新运行 `make release`，系统即可通过校验并顺利完成发版与 GitHub Actions 云端打包。
